# Clean-environment verification of spatial release candidate 11.10.0-rc7

This package was run in a new Windows 11 / CPython 3.14.0 virtual environment, outside the study project's installed Python environment. The 17-package resolved dependency lock matched `pip freeze`; `pip check` found no broken requirements. Six included unit/contract tests passed. The GEO archives, author RDS metadata, twelve selected Zenodo sections and pathology annotations matched the frozen SHA-256 reference. The runner received no previous score, QC, effect, edge-ledger, support-rollup, or figure table.

The raw-input run returned `PASS_RAW_TO_E4_S14BIPQ_INDEPENDENT_ESTIMAND_FIG2_FIG3`. All 37 GSE294385 source sections (11 dataset-local patients; 341,328 annotated spots) were rebuilt from raw matrices and author RDS labels. All 12 selected Valdeolivas sections (six dataset-local patients) passed effect-blind barcode, coordinate, and annotation QC. Fixed E4 eligibility retained nine external sections/six patients, 31 source sections/11 patients for all sites, and seven source primary-CRC sections/five patients. Failed sections and attempted offsets were preserved.

The six E4 output tables matched the archived project tables by explicit keys at absolute numeric tolerance `1e-10`: 49 combined section rows, 12 external section rows, 37 source section rows, 4,512 attempted translation rows, 22 patient-effect rows, and three patient-summary rows. There were no missing/extra keys or mismatched cells; one external float had a lexical-only `6e-17` formatting difference. This is same-data numerical reproduction, not independent validation of the biological interpretation.

The added descriptive edge audit rebuilt 20 candidate sections, 1,920 attempted shifts, and 15,360 pathology-pair-by-IS-group rows, and checked all 1,920 attempts against the freshly calculated E4 shift table. The S14p/q rollup produced 80 section-pair and 44 patient-pair rows. S14p and S14q were byte-identical to the manuscript's archived supplement; S14b had a different row order but all 15,360 keyed rows and 54 fields matched. S14i was regenerated as 80 section-pair, 44 patient-pair and eight cohort-pair records; its 132 keyed rows and 25 columns matched the archived table, with row order alone differing. Accepted shifts numbered 672 for GSE294385 primary and 723 for Valdeolivas. In the external cohort, neither cross-pathology direction reached the fixed 30/30 pair threshold at any accepted offset (0/723 each); these are non-estimable components, not zero biological effects.

Figures 2 and 3 were produced as vector PDF and 610-dpi PNG from the newly calculated tables. Both PNGs passed the quantitative figure critic's dimension, resolution and palette checks and were visually reviewed. Figure 3 is a post hoc selection diagnostic; offsets are technical controls rather than independent patient observations. This package does not generate every manuscript figure or the non-spatial analyses.

A separate arithmetic implementation reads the newly produced 15,360-row pair/group ledger and E4 reference tables. It independently computes qualifying-pair contrasts and weights, accepted-offset effects, section means, patient means, the two primary-CRC cohort means, leave-one-patient-out limits, and 10,000-draw patient bootstrap bounds. On the pre-freeze raw-input run it returned `PASS` with zero errors and reproduced the external +0.976614 percentage-point and source-primary +0.421372 percentage-point estimates, including 723/672 accepted section-offsets. This checks the estimand aggregation, not the upstream graph or expression processing.

The historical originally executed E4 script was not recovered. The current implementation reproduces archived numerical outputs, but the run cannot establish byte-identical historical execution. Windows/Python 3.14 is the only environment certified here. Local run manifests and logs contain absolute paths and are not shipped in the ZIP; the package contains sanitized code, fixed analysis configuration, protocol, tests, and this verification summary. The exact extracted ZIP must pass `verify_release.py` and the same public-input run before deposition.
